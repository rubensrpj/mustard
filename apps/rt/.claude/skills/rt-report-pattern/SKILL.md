## Purpose

A `run` command in these four families never prints its findings directly: it builds a `*Report` struct and hands it back, and a thin CLI entry serializes it. That split is what makes the commands composable — `doctor` renders several check reports into one OK/WARN/FAIL listing, `close-orchestrate` folds gate reports into its own, and the subproject guard requiring deterministic, byte-stable `run` output is satisfiable because the whole answer is one serde value with sorted vectors and no clock. It is also what makes them testable: a check that is handed a `&Path` root has a `tempdir` for a full fixture. Reports are honest about what they could not measure — an unreadable input becomes an entry in an errors vector, and a check that cannot judge at all returns `None` rather than a report full of false positives.

## Convention

Beyond the census facts, what the exemplars show:

- **`commands/maint/**` loads two molds.** This one and `rt-record-pattern`, which owns the `*Record` + `Maint<X>Report` pair of the `maint-*` fan-out commands. Where both speak about the same file, rt-record is the specific rule and wins; everything below is the general one.
- **Name and place.** `<Concern>Report` (`CapabilityDriftReport`, `ClaudePathsReport`, `MaintValidateReport`, `RehookReport`, `CloseReport`), declared near the top of the command module, after the constants and before the builder. A module that owns exactly one report may name it plain `Report` (`claude_dir_prune`, `language_audit`).
- **Derive set.** `#[derive(Debug, Serialize)]` is the norm — every report in `pipeline/` and `review/`, and every doctor check the renderer folds, carries it; `Clone, PartialEq, Eq` are added when tests compare whole values (`capability_drift_check`, `guards_scaffold_check`, `finding_collect`, `pr_publish`). Two kinds of deliberate exception: the four maint receipts nothing compares derive `Serialize` alone (`claude_dir_prune`, `rehook`, `unhook`, `worktree_gc`), and `doctor/language_audit.rs`'s `Report` derives `Debug` only — it never travels as a serde value, because that command authors its JSON with a `json!` at the print boundary and adds `ok`/`strict` there. `Deserialize` is never derived — nothing reads these back.
- **Visibility.** `pub` when the doctor renderer or another command consumes it; `pub(crate)` for reports that stay inside the crate. Fields are `pub` with a `///` line each.
- **Field order and vocabulary.** A judging command puts its verdict first — `ok: bool` (all six folded doctor checks, `finding_collect`, the three `pr_door` reports, `pr_publish`) or `overall: &'static str` with a closed word set (`"pass"`/`"fail"`/`"skip"`) — then counts, then the collection of row structs (`Vec<*Item>` / `Vec<*Entry>` / `Vec<*Record>`), then the errors vector (`scanned_errors`). A command whose report is a RECEIPT of what it did leads with the run's own parameter instead and puts the verdict, if it has one, right after: `MaintValidateReport { dry_run, overall, validates }`, `CloseReport { spec, overall, gates, … }`, `RehookReport`/`UnhookReport { scope, … }`. The pure inventories carry no verdict at all (`worktree_gc`, `claude_dir_prune`, `adapt_cursor`, `review_dispatch`) — nothing there passes or fails, and inventing an `ok` for them would be a second source of truth. Optional fields carry `#[serde(skip_serializing_if = "Option::is_none")]` so the shape stays stable.
- **Builder split.** Two shapes, decided by whether the command is a check the `doctor` renderer folds or a CLI entry of its own. The six folded checks ARE their builder: `#[must_use] pub fn run(root: &Path) -> XReport` (or `-> Option<XReport>`) takes the root as an argument and returns the struct without printing — `capability_drift_check` and `guards_scaffold_check` split the work once more into a private `fn build_report(root: &Path, …) -> XReport`, while `doctor_claude_paths`, `doctor_i1`, `doctor_workspace_leaks` and `superseded_check` build inline. Everywhere else `pub fn run(opts: XOpts)` is the CLI entry: it prints `serde_json::to_string_pretty(&report)`, emits the economy operation event, and calls a private builder that takes exactly the inputs the command varies — a root it resolved at the top and handed down (`close_orchestrate`, `language_audit`'s `audit(&cwd)`, `rehook`'s per-directory `restore_one`), or, for the two `maint-*` fan-outs, no root at all (`fn validate_all(dry_run: bool)`, `fn install_all(dry_run: bool)`), which read `std::env::current_dir()` themselves because the set of subprojects they fan over IS defined by where the operator invoked them. See rt-record-pattern for that pair.
- **Determinism.** Every vector is sorted before the struct is built (`drifted.sort_by(…)`, `errors.sort()`), and a small helper returns the healthy empty document (`ok_empty()`).
- **Degradation.** A missing directory yields the empty ok report; a single unreadable file is skipped and recorded; a check with no basis to judge returns `None` (`capability_drift_check::run` with no grain model).
- **Test placement.** `#[cfg(test)] mod tests` at the bottom of the same file, driven by `tempfile::tempdir`, with at least one test asserting the same input serializes byte-identically twice.

## How to apply

Put the new command in the family folder it belongs to and register it the way the subproject guard demands (enum variant + `dispatch` arm in that family's `cli.rs`, the locked list in `tests/run_command_surface.rs`, and a real caller). In the module, declare the row struct first, then the `*Report`, then the pure builder, then `run`. Keep every `println!` at the `run` boundary and none of it below: a builder that prints cannot be folded by a composite caller, which is the whole reason `doctor` and `close-orchestrate` can render other commands' reports.

Must not: put `unwrap`/`expect` outside `#[cfg(test)]` (crate-wide deny); leak an absolute path or an unsorted vector into a serialized field; return `Result` from `run` when the honest answer is an empty report; re-resolve the process cwd inside a builder that was HANDED a `root` (the six folded doctor checks and every root-taking helper — `ac_negative_check` documents at length why its `root` is unconditional); read a clock into a report a gate, a composite command or an `insta` snapshot compares — the two kill-switch receipts are the only reports carrying a `timestamp: String` from `mustard_core::time::now_iso8601()` (`rehook`, `unhook`), because they record a mutation an operator performed once and nothing diffs them.
